# R-036 · The control-state migration must bootstrap through paths it removes

## Context

This problem was recorded during `plan` for
`feature.concorde.define-project-ontology` and concerns `src/concorde/feature_workspace.py`.

## Expected

Every lifecycle phase writes only paths returned by the active workspace protocol.

## Observed

Protocol 11 can create this attempt only below `specs/concorde/attempts/` and can record planning reflections only in `specs/concorde/reflections.md`, while final Protocol 12 must reject both locations.

## Impact

Recorded effect: worked-around. Author specification/planning/tasks through Protocol 11, implement Protocol 12 first, hash and move the complete attempt and reflection log exactly, then apply only explicitly mapped internal-path rebases before final evidence and delivery.

## Evidence

Primary concern: `src/concorde/feature_workspace.py`.

## Triage Analysis

Migrated triage record: the prior log identified the gap between the expected and observed behavior and recorded this workflow response: Author specification/planning/tasks through Protocol 11, implement Protocol 12 first, hash and move the complete attempt and reflection log exactly, then apply only explicitly mapped internal-path rebases before final evidence and delivery.

## Proposed Resolution

Define a first-class source-profile migration operation that binds old and new control-state paths without a hand-managed bootstrap sequence.

## Intervention Rationale

需要你批准 source-profile migration 的原子性、回滚和旧路径删除策略；这些会决定是否允许自动迁移生产中的 control state。
