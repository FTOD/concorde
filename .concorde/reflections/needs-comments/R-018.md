# R-018 · Understand Anything is an adapter vocabulary, not the module ontology

## Context

This problem was recorded during `plan` for
`feature.concorde.define-project-ontology` and concerns `docs/ontology.md`.

## Expected

The referenced Understand Anything model supplies reusable entity and relationship definitions for the requested recursive module architecture.

## Observed

Its formal schema has useful code/system node and directed-edge vocabularies, but `module` is only a broad package type, `Layer` is flat, scripts normalize to files, programs are absent, and physical definition files can be conflated with logical services or schemas.

## Impact

Recorded effect: assumed. Used the formal upstream schema as an adapter vocabulary, kept Concorde modules recursive, separated stable entity identity from code locator and physical file from logical entity, introduced Program, and limited the prototype inventory to architecture-significant entities.

## Evidence

Primary concern: `docs/ontology.md`.

## Triage Analysis

Migrated triage record: the prior log identified the gap between the expected and observed behavior and recorded this workflow response: Used the formal upstream schema as an adapter vocabulary, kept Concorde modules recursive, separated stable entity identity from code locator and physical file from logical entity, introduced Program, and limited the prototype inventory to architecture-significant entities.

## Proposed Resolution

Reassess the preferred type/role mapping after the prototype has real module inventories and adapter evidence.
