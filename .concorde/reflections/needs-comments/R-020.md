# R-020 · Prototype preserves contract identities while moving interface ownership

## Context

This problem was recorded during `plan` for
`feature.concorde.define-project-ontology` and concerns `specs/concorde/features/007-project-ontology.md`.

## Expected

Every contract becomes an interface inside exactly one feature design, including shared platform dependencies.

## Observed

Several `contract.*` identities are consumed by many features or describe an external platform rather than a capability Concorde provides; renaming and splitting them in the same prototype would add compatibility churn without improving ownership.

## Impact

Recorded effect: assumed. Preserved stable `contract.*` IDs as interface identities, embeds each provided interface in one owning feature, and lets consuming features reference that identity as required.

## Evidence

Primary concern: `specs/concorde/features/007-project-ontology.md`.

## Triage Analysis

Migrated triage record: the prior log identified the gap between the expected and observed behavior and recorded this workflow response: Preserved stable `contract.*` IDs as interface identities, embeds each provided interface in one owning feature, and lets consuming features reference that identity as required.

## Proposed Resolution

Evaluate `interface.*` names and an explicit external-interface registry after feature ownership and consumers are validated in the new profile.
