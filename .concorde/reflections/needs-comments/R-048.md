# R-048 · Fresh-project docsite publication needs a homepage and an optional docs collection

## Context

This problem was recorded during `plan` for
`feature.concorde.publish-project-docsite` and concerns `specs/concorde/modules/auto-docs/features/001-publish-project-docsite.md`.

## Expected

A docsite scaffolded into a project holding only Initialization Proposal 3 outputs passes `npm run check` (feature.concorde.publish-project-docsite FR-009).

## Observed

The adapter's publication gate requires a root README.md homepage (`content.home.required`) and registers the `docs/` collection unconditionally, while Initialization Proposal 3 creates neither README.md nor `docs/`.

## Impact

Recorded effect: assumed. The scaffold proposal adds a minimal project-owned README.md only when none exists, and the adapter registers the Documentation collection and navbar entry only when `docs/` exists; the homepage rule stays unchanged.

## Evidence

Primary concern: `specs/concorde/modules/auto-docs/features/001-publish-project-docsite.md`.

## Triage Analysis

Migrated triage record: the prior log identified the gap between the expected and observed behavior and recorded this workflow response: The scaffold proposal adds a minimal project-owned README.md only when none exists, and the adapter registers the Documentation collection and navbar entry only when `docs/` exists; the homepage rule stays unchanged.

## Proposed Resolution

Decide whether the module-level publication design should own an explicit minimal-project contract (a README-less homepage fallback or an initialization-created README) instead of a scaffold-time workaround.

## Intervention Rationale

需要你确认：新项目的 README.md 应由 docsite scaffold 创建（当前做法），还是由 concorde-init 创建；这决定 Initialization Proposal 3 是否需要升级。
