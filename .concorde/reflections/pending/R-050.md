# R-050 · Feature template heading disagrees with the validator's required Edge Cases section

## Context

While authoring `specs/concorde/modules/auto-docs/features/003-publish-feature-graph.md` for
`feature.auto-docs.publish-feature-graph`, the feature body followed
`templates/feature-template.md`, which placed edge behavior under a `### Edge and failure cases`
heading inside `## Usage`. Deterministic validation then ran over the whole specification.

## Expected

A feature written from the packaged format reference passes every `CONCORDE-FEATURE-002` required
section check without renaming a heading, because the template is the format authority the
`concorde-specify` Skill tells authors to follow.

## Observed

`src/concorde/understanding/validation/features.py` lists `Edge Cases` among `REQUIRED_SECTIONS` and
matches that exact heading text at H2 or H3 (`_section_at_any_level`). The template heading `Edge
and failure cases` does not match, so the new feature failed validation with
`CONCORDE-FEATURE-002: Feature section '## Edge Cases' is missing or empty` until the heading was
renamed. The 24 pre-existing maintained features avoid the problem by carrying a separate
`## Edge Cases` H2 section rather than the template's H3 under Usage, which means the template and
the maintained corpus follow two different conventions and only one of them satisfies the validator.

## Impact

One validation failure during implementation. The bounded action taken was to rename the template
heading to `### Edge Cases` so a feature authored from the template validates. Open for triage:
whether the validator should accept the more descriptive heading or the template should promote the
section to an H2 `## Edge Cases` matching the maintained corpus; and whether any other template
heading disagrees with validator expectations (`User Scenarios & Testing` and `Usage Scenarios`
are both accepted today, `Success Criteria` and `Related Features` are not validated at all).

## Evidence

- `src/concorde/understanding/validation/features.py`: `REQUIRED_SECTIONS` and
  `_section_at_any_level`.
- `templates/feature-template.md` line 45 (heading renamed in this attempt; previously
  `### Edge and failure cases`).
- Validation finding observed before the rename:
  `CONCORDE-FEATURE-002 specs/concorde/modules/auto-docs/features/003-publish-feature-graph.md Feature section '## Edge Cases' is missing or empty.`
- Maintained features use `## Edge Cases`: `grep -l "^## Edge Cases" specs/concorde/**/features/*.md`.
