# R-052 · Codex permission sandbox omits the npm-local runtime binary

## Context

While isolating R-051's argv-serialization defect, the same generated read-only policy was encoded as
a schema-correct single TOML inline profile. Codex 0.153.2 then loaded the profile, started an
ephemeral model, and attempted the investigator's first read-only shell tool in the isolated
worktree.

## Expected

Per `feature.capabilities.permission-bounded-execution` and Codex's documented `:minimal` filesystem
token, a valid native permission profile supplies the runtime paths needed to execute sandboxed
commands while retaining the declared project read/write/deny boundary. The npm installation layout
of the selected Codex executable does not prevent a permitted tool from starting.

## Observed

The model started, but its first permitted `sed` command exited 1 before reading the file. Bubblewrap
reported `execvp .../@openai/codex-linux-x64/.../bin/codex: No such file or directory`. The system
has `/usr/bin/bwrap` 0.9.0, and the reported vendor binary exists on the host as a static PIE under
the npm installation in `~/.local/lib/node_modules`. Adding that exact vendor binary as an explicit
read rule to the otherwise identical profile made the same shell command succeed.

## Impact

Correcting R-051's inline profile serialization can remove the initial configuration parse error,
but this npm-local Codex installation still cannot run investigator tools under the resulting native
profile without additional host-runtime access. Baking one user's absolute package path into the
normalized project policy would widen or destabilize the declared boundary, so the full Operation
remains fail-closed unless this separate runtime dependency is resolved or an equivalently narrow
outer sandbox is verified.

## Evidence

- `codex --version` reports `codex-cli 0.153.2`; `codex doctor` reports an npm installation under
  `~/.local/lib/node_modules/@openai/codex`.
- `command -v bwrap` returns `/usr/bin/bwrap`; `bwrap --version` returns 0.9.0.
- A schema-correct inline profile plus a no-tool prompt starts successfully; the same profile plus a
  permitted shell read produces the vendor-binary `execvp` error.
- Adding only the exact reported vendor binary as a direct read rule makes that shell read return the
  expected first line `---`.
- `src/concorde/capabilities/operation_executor.py#AgentProcessExecutor` selects the ambient `codex`
  executable and scrubs the child environment before launch.
- Official Codex sandbox documentation describes Linux bubblewrap prerequisites, while the
  permissions documentation defines `:minimal` as the platform/runtime paths common tools need.
