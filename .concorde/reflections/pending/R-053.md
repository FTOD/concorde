# R-053 · Agent process exit zero masks a capability that could not start

## Context

After implementing R-051's parser-safe Codex permission profile, the real
`concorde-reflections-triage` Operation was run against R-052. The profile loaded and the nested
Codex agent started, but every required read-only tool failed because its sandbox could not execute
the npm-local Codex vendor binary.

## Expected

Per `feature.capabilities.permission-bounded-execution`, an investigator that cannot run its
mandatory workspace gate or inspect any authorized source is a failed capability. Its enforcement
receipt reports failure, and the Operation stops every downstream node rather than accepting prose
that describes the failure as a successful capability result.

## Observed

The nested agent truthfully returned that investigation could not start, named the failed
`scripts/workspace.py --phase analyze` prerequisite, reported the bubblewrap `execvp` error, and
stated that no project files were inspected. Codex nevertheless exited 0. `AgentProcessExecutor`
derives success only from that process exit code, so the Operation emitted a receipt with
`status: success`, `exit_code: 0`, and `limitations: none` and returned the failure prose as an
ordinary successful `concorde-analyze` result.

## Impact

The investigate action happened to have no later model stage, but the same false-success boundary
can allow a multi-stage Operation to continue with an unusable prior result after a mandatory Skill
could not execute. Exit-code-only success does not establish that a capability completed its
contract, and the current receipt loses the limitation the agent explicitly reported.

## Evidence

- Reproduction:
  `python3 scripts/run-operation.py operations/concorde-reflections-triage/operation.py 'investigate R-052' --framework-prefix . --feature-path specs/concorde/modules/capabilities/features/003-enforce-permission-bounded-execution.md --execute`.
- Result output begins `Investigation of R-052 could not start because the execution environment
  failed before the mandatory workspace gate` and says no project files were inspected or changed.
- The adjacent receipt reports `status: success`, `exit_code: 0`, and `limitations: none`.
- `src/concorde/capabilities/operation_executor.py#AgentProcessExecutor.__call__` maps return code 0
  directly to success without a capability-result schema or semantic completion signal.
- `specs/concorde/modules/capabilities/features/003-enforce-permission-bounded-execution.md` requires
  executor refusal and capability failure to stop all downstream nodes.
