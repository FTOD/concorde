# R-063 · Public Operations accept an outer enforcement mode they cannot attest

## Context

`concorde-operation-configuration` exposes two enforcement values, `native` and `outer`, for both
Codex and Claude integrations. Native mode asks the selected client to enforce the compiled policy.
Outer mode is intended for a trusted host sandbox when native enforcement is unavailable. The
renderer correctly refuses outer mode unless the host supplies an `outer_sandbox` identity.

Installed public Operation scripts all delegate to `json_main`, which constructs the trusted
`OperationHost` for stdin invocations.

## Expected

Every configuration accepted at initialization and advertised by the public wire schema has an
executable public path. If outer enforcement is selected, a trusted launcher—not task JSON—attests
the active sandbox and binds that evidence to the invocation. If the distributed launcher cannot do
that, project configuration rejects outer mode before an initialized project depends on it.

## Observed

`json_main` constructs `OperationHost(Path.cwd(), package_root, mode=value["mode"])` and never sets
`outer_sandbox`. The stdin schema deliberately contains no authority field, and the wrapper script
adds no trusted side channel. When an agent stage renders an outer configuration, both integration
renderers reject it because no verified outer sandbox identity exists.

An executable consumer fixture was configured with `{integration: codex, enforcement: outer}` and
invoked through the same host construction. `concorde-ask` returned `status=failed` with
`execution_failed: Codex native permission-profile enforcement is unavailable and no outer
enforcement was verified` before any model process ran.

## Impact

A project can be initialized into an advertised configuration in which every agent-backed public
Operation is unusable. The failure is discovered at task execution rather than configuration or
initialization. Embedders can manually instantiate `OperationHost(outer_sandbox=...)`, but that is
not the installed public Operation boundary described to consumers.

## Evidence

- `src/concorde/capabilities/protocol_contracts.py` exposes `outer` in the operation-configuration
  schema.
- `src/concorde/capabilities/operation_permissions.py:400-409` and `529-538` require a host-issued
  outer sandbox identity.
- `src/concorde/capabilities/scoped_operations.py:612-629` constructs the public host without that
  identity.
- `specs/concorde/services/operation-boundary.md:9-16` documents outer as a stored supported setting.
- Branch-review fixture reproduced the failure before model launch with a matching initialized
  configuration.
