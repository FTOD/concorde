# R-064 · Converge launches and records the implement Operation identity

## Context

Profile 8 registers `concorde-implement` and `concorde-converge` as two public Operations with
separate request/response type IDs and executable entry points. Both currently use the same internal
implementation-worker role. Completion receipts, context snapshots and response
`completed_operations` are expected to preserve the public Operation identity that was invoked so
the lifecycle can be audited and replay is rejected correctly.

## Expected

Invoking `concorde-converge` binds the agent launch, completion envelope, host evidence and returned
completed-operation list to `concorde-converge`. Sharing an internal role or implementation helper
does not change the public invocation identity. If converge has no behavior distinct from implement,
the published registry does not present two independently auditable Operations.

## Observed

`_dispatch` sends both public names to `Invocation.implement()`. That method ignores
`self.operation` and hard-codes `self.stage("concorde-implement", inputs=...)`. The stage therefore
resolves and launches with the implement Operation ID and appends `concorde-implement` to the
completed list, even when the outer typed response is `concorde-converge-response`.

An executable fixture created a valid plan and tasks, invoked `concorde-converge`, and received a
successful converge response whose `completed_operations` value was `["concorde-implement"]`.

## Impact

The public request identity, native completion identity and workflow audit disagree. Consumers cannot
tell whether converge or implement actually ran, policy descriptions name the wrong Operation, and
any future divergence in their prompts, effects or gates will silently be bypassed by the hard-coded
stage. Tests that assert only the implementation phase or final success do not detect the mismatch.

## Evidence

- `src/concorde/capabilities/protocol_contracts.py:23-35` registers both names separately.
- `src/concorde/capabilities/scoped_operations.py:318-330` hard-codes the implement stage.
- `src/concorde/capabilities/scoped_operations.py:557-558` dispatches both public names to that same
  method.
- Executable fixture result: `status=succeeded` and
  `completed_operations=["concorde-implement"]` for a `concorde-converge-request`.
