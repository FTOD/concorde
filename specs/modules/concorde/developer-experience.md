# Developer experience

The root Module offers complementary views through Publication and Viewer. Publication presents
authored Module contracts, internal architectures, Implementation Specs and their declared
relationships. Viewer opens an existing raw code graph; observations there do not silently alter
intended behavior. A developer can identify a feature, interface, dependency or source and supply
a question or correction. Workflows turns the clarified intent and constraints into a bounded
request. Ordinary feedback needs no separate Reflection record; durable gaps may be explicitly
recorded through Reflections. Viewing or commenting does not itself authorize a code change.
