# Feature Design: Provider API

## Outcome and Scope

Publish one provider API without exposing private implementation.

## Architecture Zoom

| Entity ID | Role |
|---|---|
| `entity.example.provider-service` | Implements the published interface. |

## Interfaces

### `contract.provider.api` — Published provider API

- **Consumer**: Consumer module
- **Direction**: Consumer request to provider result.
- **Entry points**: `entity.example.provider-service`
- **Inputs**: One API request.
- **Outputs**: One stable result.
- **Obligations**: Preserve the published behavior.
- **Failures**: Invalid requests fail without mutation.
- **Compatibility**: Stable fixture contract.
- **Implementing entities**: `entity.example.provider-service`

## Usage Scenarios

1. A consumer calls the published API.

## Requirements

- **FR-001**: The API returns a stable result.

## Edge Cases

- Private source remains out of consumer context.
